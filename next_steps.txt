NEXT STEPS TO MAKE AGRICONNECT FULLY FUNCTIONAL

1. ENVIRONMENT VARIABLES
- Backend: backend\.env already exists. Fill the required values:
  - JWT_SECRET: generate a long random string (e.g. ode -e "require('crypto').randomBytes(32).toString('hex')")
  - CLOUDINARY_CLOUD_NAME / CLOUDINARY_API_KEY / CLOUDINARY_API_SECRET (cloudinary.com)
  - RAZORPAY_KEY_ID / RAZORPAY_KEY_SECRET / RAZORPAY_WEBHOOK_SECRET (dashboard.razorpay.com, test mode)
  - FIREBASE_SERVICE_ACCOUNT_PATH: optional for dev
  - GOOGLE_MAPS_API_KEY: optional

- Frontend: frontend\.env has VITE_API_BASE_URL=http://localhost:5000. Add VITE_RAZORPAY_KEY_ID if using Razorpay.

2. DATABASES (YOU NEED THESE RUNNING)
Option A (Docker): docker compose up -d postgres mongodb redis
Option B (Native): Start PostgreSQL (5432), MongoDB (27017), Redis (6379)

3. CREATE SCHEMA + SEED DATA
cd backend
npx prisma db push
npm run prisma:seed

4. START SERVERS
Terminal 1: cd backend && npm run dev  (API: http://localhost:5000)
Terminal 2: cd frontend && npm run dev (UI:  http://localhost:5173, proxies /api -> :5000)

6. ABOUT docker-compose.yml
It defines postgres/mongodb/redis/backend/frontend. If you have NOT created those containers yet, running docker compose up -d will pull/build and create them. Keys/secrets in compose should never be real production secrets. You don't need to create containers manually � up does it.

7. GITIGNORE FILES
Add proper .gitignore files to avoid committing secrets/builds:
- Root: ignore .env, node_modules, dist, build, .vscode, .DS_Store, *.log
- backend: ignore dist, .env, node_modules, prisma/migrations/*.db (if any), coverage
- frontend: ignore dist, .env, node_modules, coverage, .vite
